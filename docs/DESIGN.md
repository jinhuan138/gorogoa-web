# 详细设计

## 目标与验收边界

最终验收目标是：所有章节可按原版流程通关；画面、裁切、层级、相机、热点、状态转换、动画时序、声音与原版对照一致。网页必须在 GitHub Pages 仓库子路径下运行，资源分批加载，支持鼠标；触摸交互在桌面行为一致后补齐。

“原版一致”需要逐场景、逐步骤验收，不能由资源导出成功或静态代码分析来证明。目前的素材核对页属于开发校验工具，后续由实际游戏入口替换；不将其标记为可玩游戏。

## 已恢复的数据模型

正式版项目包含 25 张 Card、70 个 Scene、452 个 SceneLocation、575 个 SceneLayer、1434 个 StateFlag、1244 个 StateTransition、640 个 LocationTransition、3927 个 AtomicPredicate、2022 个 CompoundPredicate、625 个 MotionKeyframes 和 81 个 CardLink。

正式版初始卡片是 card002，初始位置为 city1a000，具体 GUID 保留在项目配置中。卡片并不等于章节；章节初始存档另有 chapters/chapter1 等资源，必须分别导入。

数据转换保留 GUID、XML 元素类型与顺序、浮点数、状态引用、关键帧和原始枚举。不将关键帧取整，不用素材文件名推测关卡顺序。演示版与正式版存在同名素材，必须经 ResourceManager 的资源路径区分，不能用同名第一条匹配。

## 模块和实现顺序

1. **资源与项目导入**：解析原版项目 XML，创建 GUID 索引，导入图集裁切与初始存档。缺失引用明确报错。路径正规化后解析原版工程目录与打包资源之间的对应关系。
2. **静态场景渲染**：Canvas 2D；实现图层、裁切、相机坐标、透明度和背景继承。先固定原版的一个静态位置，以同分辨率截图校验；只有证实 2D 能覆盖所需相机变换后再推广。若投影/遮罩无法等价，先记录差异，再评估原生 WebGL，无需增加游戏引擎依赖。
3. **谓词与状态**：按原版语义实现 AtomicPredicate、CompoundPredicate、StateTransition。未识别的谓词和图形类型必须保留为未知并阻止错误触发，不能默认为真。按原版顺序处理状态、动画完成、进入位置等事件；解析公式时不用 eval。
4. **操作与卡片关系**：统一指针输入、四格摆放、拖动、分离与叠合、CardLink、热点、缩放。记录一次操作前后状态，复现原版的取消、非法摆放和动画中输入行为。
5. **动画与特效**：插值、位移、旋转、缩放、播放列表、反向播放、中断、遮罩、阴影、色调、模糊和视差。恢复的 625 个 MotionKeyframes 不是独立动画数量，需要按引用和播放列表组装。
6. **特例脚本**：项目引用三类脚本（NeedleScript、FireScript、TwinkleScript），共 6 个实例。先分析主程序集实际代码，再逐类实现，不用效果近似替代逻辑。
7. **声音与存档**：解析 AudioClip、外部资源块和事件时间表；转换格式前检查本机已有解码工具。使用浏览器 Web Audio，并按原版声道、循环、音量和事件时序对照。将全部关卡状态与卡片堆叠序列化，进行版本标记，验证刷新恢复。
8. **全流程和发布**：按章节重复验证。筛选正式版被引用素材，去掉重复和演示版输出，按需加载与释放图集；保留本地分析结果。确认发布体积、资源路径、音频首次播放与触屏行为后，再由用户批准提交和发布。

## GitHub Pages

- Vite `base: './'`，资源地址相对部署入口解析。
- 无后端，不依赖服务器重写或跨域隔离响应头。
- 暂不使用路由框架与 Service Worker，避免引入额外状态与缓存问题。
- 工作流仅 `workflow_dispatch`，不会由 push 自动发布。
- 当前恢复的全部 PNG 约 792 MiB，尚未加入声音且包含演示版。必须以正式版依赖图筛选并核对最终站点体积，不能现在宣称已满足发布验收。

## 验证办法

- 数据：来源哈希、对象边界、图集区域边界和原始尺寸，正式版与演示版引用分别检查。
- 纹理：BC1/BC3 单色、透明、alpha 分支、边缘块和截断输入；PNG 容器尺寸与像素解压；抽样视觉检查。
- 行为：每个谜题记录原版操作序列、输入前后状态、画面和音频时刻，再在网页执行同序列比较。
- 画面：相同窗口尺寸、位置和时间点截图，分别核对构图、裁切、层级、颜色与动画相位；记录浏览器/GPU 引起的差异，不提前承诺跨平台逐像素一致。
- 回归：章节起点、关键分支、回退、非法操作、存档恢复、最终通关。
- 按用户要求，不由代理执行 build / 编译；构建验证由用户本地执行。未经构建与实际 Pages 访问，不能将发布配置称为已验证部署。
