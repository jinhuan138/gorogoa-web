# 详细设计

## 目标与验收边界

最终目标是：所有章节都能按原版流程通关，画面、裁切、层级、相机、热点、状态转换、动画时序和声音均与原版一致。网页必须能在 GitHub Pages 仓库子路径下运行，资源分批加载，同时支持鼠标和触摸。

“与原版一致”需要逐场景、逐步骤验收，不能靠资源导出成功或静态代码分析来证明。游戏入口为 `index.html`；素材核对页 `assets.html` 只是开发校验工具，不是可玩游戏。

## 已恢复的数据模型

正式版项目包含 25 张 Card、70 个 Scene、452 个 SceneLocation、575 个 SceneLayer、1434 个 StateFlag、1244 个 StateTransition、640 个 LocationTransition、3927 个 AtomicPredicate、2022 个 CompoundPredicate、625 个 MotionKeyframes 和 81 个 CardLink。

正式版的初始卡片是 card002，初始位置为 city1a000，具体 GUID 保留在项目配置中。卡片不等于章节；章节的初始存档另存于 chapters/chapter1 等资源，必须分别导入。

数据转换保留 GUID、XML 元素类型与顺序、浮点数、状态引用、关键帧和原始枚举；关键帧不取整，也不用素材文件名推测关卡顺序。演示版与正式版存在同名素材，必须经 ResourceManager 的资源路径区分，不能取同名的第一条。运行时逻辑树只剔除编辑器元数据（如 `fieldModificationLog`、`deletionLog`、`lastModified`），其余内容可用 `prepare-runtime.ps1 -VerifyOnly` 与原版 XML 逐节点核对。

## 分层

- **渲染**：`src/engine/render/` 用 Canvas 2D 实现相机矩阵、视差、遮罩、镂空和雾效，结局混合使用 WebGL。图集按需解码，离开场景后按 LRU 回收；鼠标悬停或按下热点时，按导航目标有限预取，最多 2 张、解码像素约 32 MiB。设备像素比上限为 2。
- **动画采样**：`src/engine/animation.js`、`model/board.js`、`model/navigation.js` 按原版数据逐帧采样插值，保留 `Math.fround`、截断和反向关键帧等细节；采样函数以 elapsed 为参数，不保存状态。
- **运动控制**：`src/game/motion.js` 按 navigation、flight、opening、closing 的顺序调用采样函数，完成时先清空槽位，再回调。
- **界面时间线**：`src/game/timeline.js` 用 Anime.js 编排启动页和片尾名单的淡入淡出，关闭自动播放，由游戏的冻结时钟 seek 推进。
- **流程**：`src/game/runtime.js` 负责棋盘交互、剧情推进和音频生命周期。每帧依次执行运动、脚本、链接与状态、剧情、自动导航、音轨同步和绘制。页面转入后台时冻结游戏、启动页与结局时钟并暂停音频；恢复时保留菜单的暂停状态。
- **声音**：`src/engine/audio/` 按原版事件表播放环境、动画和配乐；`interface.js` 按原版 Startup 绑定播放菜单与热点音效，4 个并发音源，每组洗牌后循环，并随机音量与音高。
- **界面**：`src/ui/` 的 Vue 组件提供菜单、设置、章节、语言、制作人员名单和热点，动作集中在 `useGame.js`。游戏名称随界面语言显示为“画中世界”“畫中世界”或“Gorogoa”；首次运行按浏览器语言偏好选择，已保存的手动设置优先。

## 实现顺序

1. **资源与项目导入**：解析原版项目 XML，建立 GUID 索引，导入图集裁切和初始存档；缺失引用明确报错。路径正规化后，解析原版工程目录与打包资源之间的对应关系。
2. **静态场景渲染**：使用 Canvas 2D 实现图层、裁切、相机坐标、透明度和背景继承。投影或遮罩无法等价时，先记录差异，再评估原生 WebGL，不引入游戏引擎依赖。
3. **谓词与状态**：按原版语义实现 AtomicPredicate、CompoundPredicate 和 StateTransition。未识别的谓词和图形类型保留为未知，阻止错误触发，不能默认为真。状态、动画完成、进入位置等事件按原版顺序处理；解析公式时不用 eval。
4. **操作与卡片关系**：统一指针输入，实现四格摆放、拖动、分离与叠合、CardLink、热点和缩放，复现原版的取消、非法摆放和动画中输入行为。
5. **动画与特效**：插值、位移、旋转、缩放、播放列表、反向播放、中断、遮罩、阴影、色调、模糊和视差。625 个 MotionKeyframes 并非独立动画的数量，需按引用和播放列表组装。
6. **特例脚本**：项目引用 NeedleScript、FireScript、TwinkleScript 三类脚本，共 6 个实例。依据主程序集的实际代码逐类实现，不用近似效果代替逻辑。
7. **声音与存档**：解析 AudioClip、外部资源块和事件时间表，使用 Web Audio，按原版声道、循环、音量和事件时序对照。全部关卡状态与卡片堆叠序列化并标记版本，验证刷新后能恢复。
8. **全流程与发布**：逐章验证，只发布正式版实际引用的素材，按需加载和释放图集，保留本地分析结果。

## GitHub Pages

- Vite 设为 `base: './'`，资源地址相对部署入口解析。
- 无后端，不依赖服务器重写或跨域隔离响应头。
- 不使用路由框架和 Service Worker，避免引入额外的状态与缓存问题。
- 工作流在推送到 `main` 或手动触发时运行：先执行单元与通关回归、纹理与素材校验，全部通过后再构建并部署。
- 发布集合按真实引用筛选，共 1036 项，静态资源约 616.80 MiB，完整构建约 618 MiB。

## 验证办法

- 数据：来源哈希、对象边界、图集区域边界和原始尺寸，正式版与演示版引用分别检查。
- 纹理：BC1/BC3 单色、透明、alpha 分支、边缘块和截断输入；图片容器尺寸与像素解压；抽样视觉检查。
- 行为：每个谜题记录原版的操作序列、输入前后状态、画面和音频时刻，再在网页上按同一序列执行并比较。
- 画面：以相同窗口尺寸、位置和时间点截图，分别核对构图、裁切、层级、颜色与动画相位；记录浏览器或 GPU 造成的差异，不承诺跨平台逐像素一致。
- 回归：章节起点、关键分支、回退、非法操作、存档恢复和最终通关。
- 发布：以 CI 构建成功和实际访问 Pages 为准，本地构建通过不等于远端部署已验收。
